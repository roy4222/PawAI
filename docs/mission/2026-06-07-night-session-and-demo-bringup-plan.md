→ 這張圖是「距離/小物」問題的活證據（見 session 傳的 `objframe.jpg`）。

### 🔑 為什麼「不換模型」（PINTO / coco_detector）— 講清楚

**A. 為什麼不採用 PINTO 挖到的模型**
- PINTO_model_zoo = 一個 482 個現成模型的大集合，我們 6/04 研究過（`docs/archive/pawai-brain-legacy/research/2026-06-04-pinto-model-zoo-full-analysis.md`，891 行）。
- **杯子遠距抓不到的根因是「像素物理」不是「模型笨」**：9cm 的杯子 @2m，在 640 解析度下只剩約 **21 像素**。資訊量就那麼多，**換哪個模型都是吃同樣 21px**，換不出資訊。今晚白馬克杯 @1.5m、人眼清楚、YOLO26n `Det:0` 就是鐵證。
- 真正能救遠距小物的只有：①拉高輸入解析度(960→約32px，但 YOLO26n ONNX 固定 640、要重匯 + 風險) ②**放近 / 用大物體**。
- **所以「為了遠距小杯子換模型」= 白費**。你的 PINTO 研究沒白做——它的價值就是**證明了瓶頸是物理、省下我們亂換模型的時間**。

**B. coco_detector（go2_ros2_sdk 裡那個）到底是什麼、要不要用**
- 位置：`.tmp/go2_ros2_sdk/coco_detector/coco_detector/coco_detector_node.py`（上游 go2_ros2_sdk clone 裡，確實存在）。
- 我讀過 code：用 **torchvision FasterRCNN-MobileNet-v3-320**（PyTorch、預設跑 CPU、信心門檻 0.9）。訂 `/camera/image_raw`、發 `Detection2DArray` + 標註圖。
- ✅ 好處：開箱認**全 80 類** COCO。
- ❌ 壞處：**精度低**（COCO mAP ~22，我們 YOLO26n ~40，差一倍）、**CPU + PyTorch 在 Jetson 慢**。
- **結論：不要換它當主偵測器**（更不準更慢）。

### ✅ 物體辨識真正的問題 + 快速 win（這才是重點）
- **我們現在把 YOLO26n 用得超爛是真的**：demo 故意只開 **cup 一類**（`class_whitelist:[41]`），等於 80 類只用 1 類、1/80 火力。
- **快速 win（幾乎零成本、零風險）**：**打開白名單** → YOLO26n 本來就會認全 80 類 COCO，免費拿到多物體辨識。今晚我試了但 launch 參數沒吃到（要改 `object_perception.yaml` 或修 launch），明天弄。
- **大物體比小杯子準很多**（像素多）：椅子/沙發/電視/筆電/桌子/瓶子/書/盆栽… 都在 COCO，且大物體偵測穩。**demo 改用「多個大物體 + 近距杯子」→ 讓評審看到它一次認出滿屋東西，比硬秀遠距小杯子強。**
- **你要的「讓評審感受視覺辨識多厲害 / VRM 感」**：可行方向 = 開白名單 + 即時多框 + Studio object panel 顯示「我看到 椅子、沙發、杯子…」。VRM/場景級可能來不及，但「多物體即時辨識」絕對做得到，且大物體穩。
- **家用資料集 / 別的 YOLO**：可調查（你提到的方向），但**最快、最穩的是先把現有 YOLO26n 的 80 類開出來 + 用大物體**，不必先換資料集。
