## Tasks

1. Read each input result. Extract its filled verdict slot and the top 3 findings supporting it.
2. Build a **contradiction matrix**：特別檢查這幾條已知耦合——
   - goal 1 的勝出配置 vs goal 2 的 open-vocab 模型尺寸（同尺寸才公平、或同一顆模型雙解）
   - goal 1 的 seg 裁決 vs goal 3 的 GO_SEG_MASK_COLOR 路線

3. Build a **unified decision table**: one row per sub-bottleneck（cup 遠距 / 類別 / 顏色 / pose 手勢 / 輪廓）。Columns: sub-bottleneck / supporting deepdive(s) / verdict / confidence / next action.
4. **產出單一上機測試日清單**（本 synthesis 的核心交付）：
   - 每項：配置名 / WSL 前置動作（export、資料準備、腳本）/ Jetson 上量什麼 / pass-fail 門檻 / 預估時間（含 TRT engine build 3-10 分/個）
   - 按依賴排序（先燒 engine 的先排）、標注哪些可平行、總時長估算（半天/全天）
   - RAM/GPU 預算總表：所有入選配置同跑或輪跑的安排，守 ≥0.8GB 紀律
   - 把既排定的 spike 一併編入：supervision ByteTrack 離線 spike、478_SC 離線對照（若已完成則引用結果）
5. List unresolved cross-cutting questions (claims no single deepdive owned).
6. Recommend next-step actions: commit / new `/goal-research` invocation / new test goal / ADR draft / plan update.

## Verdict slot (REQUIRED — synthesis has its own verdict)

Pick exactly one:
- `READY_TO_COMMIT` — decision is unambiguous; recommend specific commits and which existing branch/PR to land them on
- `READY_TO_ADR` — decision is hard-to-reverse and surprising; the user should formalize it as an ADR before committing
- `NEEDS_NEW_RESEARCH` — list the specific gap(s) and the suggested `/goal-research` follow-up invocation
- `BLOCKED_BY_HARDWARE_TEST` — list the specific test goal that must run first（本案預期高機率落在這格：清單完成、等上機）
- `INCONSISTENT` — deepdive verdicts contradict each other in ways that need a second round of grill or replanning; do not proceed to implementation
